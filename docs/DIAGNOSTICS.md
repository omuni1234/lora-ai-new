# 日本語のError・Warningと管理画面（v0.6）

## 画面構成

- 左：実験設定メニュー。選択項目と診断件数を表示します。
- 中央上：実験前プレビュー。右下をドラッグして高さを変更できます。表示範囲、ED上限、軌跡等は「表示範囲・プレビュー設定」、選択EDの定数は下部の詳細から確認します。
- 中央下：選択した設定の編集フォーム。独立してスクロールできます。「基本設定」の折りたたみ欄にプロファイルの保存・読み込みとExperimentの選択があります。
- 右：選択Runの状態・進捗・経過時間、保存された診断、実行キュー、結果アブストラクト、出力ファイル。

861px以上の画面幅では3列です。761〜860pxでは結果欄を下に移し、小さな画面では縦に並べます。比較・分析、モデルライブラリの画面も引き続き利用できます。

設定変更後はプレビューに「設定変更あり」と表示し、前回の画像を薄くします。「設定を確認する」で再計算します。実行中のパケット・移動を配信する機能ではありません。プレビュー計算中に設定が変わった場合は、古い応答を適用しません。

## Error

赤いカードに日本語の説明、修正ヒント、特定できる場合は設定パスを表示します。設定パスのリンクから対象メニューと入力欄へ移動できます。Errorとなった入力欄は赤く表示します。アクションの失敗は画面上部、設定チェックは中央、Runの失敗は右側に表示されます。

主な対応範囲：

- 数値の上下限、型、必須項目、未知のキー、選択肢、非有限値、YAMLの行・列。
- 重複ID、帯域重複、UL/DL許可、RX1/RX2、SF×CH、配置件数、モデル参照。
- 周期の揺らぎ・開始時刻、ウェイポイント・マルコフ遷移、DQNのバッチ・探索率等。
- 独自プラグインの許可・読み込み・インターフェース。
- 実行中の不正時刻・座標・送信パラメータ、ペイロード上限、伝搬バッファ上限、DQNの非有限損失。
- 認証、存在しないRun・ファイル、分析範囲、保存権限、空きディスク容量不足、workerの終了・生存通知途絶。

元の例外メッセージは「技術詳細」で確認できます。**未知の例外や独自プラグインの任意のメッセージについて、原因を推測した翻訳はしません。** 日本語で処理失敗と確認方法を案内し、元の情報を保持します。既知のメッセージに対応するルールは `lorasim/diagnostics.py` の `RULES` にあります。

実験中の失敗はSQLiteのRunに構造化診断と元のエラーを保存します。出力先に書き込める場合は `error.log` にトレースバックも保存します。ログ書き込みに失敗しても、それによって元の例外を置き換えません。GUIを再接続した後はキューの「原因を確認」で参照できます。OSによる強制終了等で例外を保存できなかった場合、workerの終了コード・生存通知から説明し、原因を断定しません。保存先DB自体が利用できない場合は、API/worker/OSのログで復旧する必要があります。

## Warning

黄色いカードは設定の再確認を促すもので、実行を禁止したり、定数を変更したりしません。確認のための追加ダイアログもありません。APIは成功応答のまま診断を返します。

| コード | 発生条件と意味 |
| --- | --- |
| `DUTY_DISABLED` | Duty cycleが無効。送信数・衝突条件が変わる |
| `PROPAGATION_SPEED` | 信号の伝搬速度が既定299792458 m/sと異なる。EDの移動速度との取り違えを確認 |
| `PATH_LOSS_EXPONENT` | 対数距離モデルの指数が2未満または6超。この範囲は注意目安であり理論上の許容範囲ではない |
| `ALOHA_MATRIX` | goursaudと異なる比較用の干渉行列を使用 |
| `NONDEFAULT_RADIO` | 公開候補のCR、プリアンブル、暗黙ヘッダ、CRCに既定値と異なる値がある |
| `UNLISTENED_CHANNEL` | モデル定義の候補CHに、どのGWも受信しない周波数がある |
| `NO_GW_CHANNELS` | 全GWのUL受信周波数が空 |
| `START_AFTER_END` | 周期送信の最も早い開始が実験終了時刻以降 |
| `LARGE_LEARNING_RATE` | DQN/SEMAの学習率が経験的な注意目安0.1超。既定0.01との差を確認 |
| `NO_EXPLORATION` | DQNの初期探索率が0（探索率の順序制約により最終値も0） |
| `REWARD_ORDER` | 不達報酬が候補SFの少なくとも1つの成功報酬以上 |
| `LINUCB_NO_POSITION` | グループのLinUCBに位置観測を与えないため速度特徴量が0 |
| `LINUCB_NO_EXPLORATION` | UCB探索係数とランダム探索率がともに0 |
| `EXP3_UNIFORM` | LoRa-MABのgamma上書きが1で、学習後も一様選択 |
| `NEGATIVE_LINK_MARGIN` | ADR/G-ADRのリンク余裕が負 |
| `RADIO_ENERGY_OFF` | 無線消費エネルギーの計算が無効 |
| `MCU_MEASURED` | ホスト実測時間をMCU計算時間に使うため実機との差・環境依存がある |
| `NOTIFICATION_FAILED` | curlの進捗通知が失敗。本体のシミュレーションとは別の失敗 |
| `NOTIFICATION_LOG` | 進捗通知ログの保存失敗 |

モデルの確認は、参照先と上書きを解決したグループ・条件割り当ての各**定義**に対して行います。上書きで使われない定義にもWarningが出ることがあり、適用条件を確認するよう案内します。未知の独自アルゴリズムに内蔵モデルの経験的閾値を適用しません。Optionsによる型・制約検証と、実行中の例外表示は独自モデルにも共通です。

Warningは網羅的な妥当性証明ではありません。選択器の学習後の返値、独自コードの全分岐、実行環境の将来の障害を静的に判定するものではありません。

## 検証と性能

入力を止めて約900 ms後に設定形式・公開Options・Warningをチェックします。この軽量チェックはEDや学習器を構築せず、イベントを実行しません。グループと割り当ての定義数に応じた処理です。古い非同期チェック結果は変更後の設定に適用しません。

「設定を検証」および保存・実行登録では従来通りモデルの初期化も検証します。この処理はED数・モデルサイズの影響を受けます。「入力チェック済み」と「検証済み」を区別しています。

診断処理を無線・干渉・イベント処理のループへ追加していません。停止フラグの確認も診断JSONを展開せずに取得します。実行のポーリングは従来の4秒間隔・表示中タブだけです。通知失敗は通知スレッドから保存し、コードと設定パスごとにまとめるため件数が通知回数に比例して増えません。

## API・保存形式

エラー応答は従来のHTTPステータスと `detail` に加え、次の `diagnostics` を返します。通常の設定違反は422、認証は401、サーバー側の予期しない例外は500です。`detail` は先頭の日本語説明です。

```json
{
  "detail": "シミュレーション時間 [s]: 0.0より大きい値が必要です。",
  "diagnostics": [{
    "code": "VALIDATION_GREATER_THAN",
    "severity": "error",
    "path": "duration_s",
    "message": "シミュレーション時間 [s]: 0.0より大きい値が必要です。",
    "hint": "入力値と単位を確認し、指定範囲に修正してください。",
    "detail": "Input should be greater than 0"
  }]
}
```

- `POST /api/diagnostics`: `{yaml: "..."}` を受け取り、軽量検証の `diagnostics` と `scope: configuration` を返します。
- `POST /api/validate?report=true`: モデル初期化も検証し、`{profile, diagnostics}` を返します。既存の `/api/validate` はプロファイル単体を返す契約を維持します。
- `POST /api/jobs`: `{id, diagnostics}`。登録時のWarningをRunに固定します。
- `GET /api/jobs/{id}`: 既存フィールドと `diagnostics`。実行中のError・通知Warningを確認できます。
- `POST /api/preview`: 既存のプレビュー結果に `diagnostics` を追加します。

`path` はドット区切りの設定パスで、配列添字は0始まりです。原因の位置を特定できない場合は空文字です。`detail` は表示用に最大8000文字とし、完全なトレースバックは保存可能な場合の `error.log` を参照します。RunのDBに `diagnostics TEXT` 列を追加する移行は起動時に行います。既存の `error` 列・ファイル形式・物理モデルは維持し、古いRunのエラーは読み出し時に診断へ変換します。

新しい検証ルールを加える場合は、モデルのハード制約をOptionsに、経験的な注意目安を `configuration_warnings` に分けて記述してください。メッセージには観測事実、ヒントには具体的な修正箇所を記載し、禁止条件と注意目安を混同しないでください。フロントエンドはメッセージをtextContentで扱い、例外のHTMLを実行しません。
