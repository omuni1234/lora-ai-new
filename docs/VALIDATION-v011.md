## 自動検証

- macOS arm64 / Python 3.11：**314 passed**、10.42秒。[ログ](../validation/tests-experience-v011.txt)。既存のStarlette TestClient非推奨警告1件。
- JavaScript：**8 passed**。[ログ](../validation/tests-experience-ui-v011.txt)。地図の距離尺度、ゼロ送信の時系列描画、既存配置プレビューを含む。
- JavaScript構文、`git diff --check`、`docker compose config -q`通過。

主な追加検証：

- 静止100・移動100で、1静止地点なら全経験の50%、2地点なら25%。最長連続100対50、実効地点数1対2。
- 静止地点に集中していても滞在と送信の分布が一致すればTVは0。集中度と時間分布からのずれを混同しない。
- 巡回移動で送信位置が同じでも移動中と判定。周期境界での判定も検証。
- 0生成をnullとし、終了端は除外。予算超過は日本語HTTP 422、Runを登録しない。
- ED別の初期配置乱数とモデル割当、シード再現性、入力非破壊、Poissonの生成時刻。
- 選択器を変更しても経験確認結果は変わらず、選択器のインスタンスを構築しない。
- 静止、Random Walk、Markov、Waypoint全3方式で、状態公開を繰り返しても位置・乱数軌跡が変わらない。
- 状態未公開を不明として扱い、preview_safe未宣言モデルは実行しない。

## 計測・画面

500 ED、共通100 Waypoint、速度0.5〜1.5 m/s、静止100〜600秒、600秒周期・初回0〜600秒、24時間から32 EDを標本化。時間標本1024/EDで **0.172秒**（単一のローカル計測）。これは有界な事前確認の処理時間であり、500台の実通信を走らせる時間でもUbuntu実機の保証値でもない。

ブラウザーで例19を読み込み、Calculator→経験分布→確認、ED0/ED1の切替、静止・移動100/100と50%/25%の差を確認した。空欄の自動終了時刻を任意項目として扱うことも確認した。
