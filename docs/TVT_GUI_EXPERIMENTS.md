# TVT性能評価：Experiment YAMLとGUI分析

修論第5章の基準実験と追加対照実験を、既存のExperiment形式とプラグインAPIで実行します。`examples/tvt/`に本実験76設定と機能確認1設定を同梱しています。各YAMLは**1手法だけで構成する独立ネットワーク**です。

## GUIで読み込み・実行する

実行前にAPIとworkerの両方を、このTVT実装を含む同じコミットへ更新してください。新しいプラグインと計測に対応していない旧workerでは実行できません。既存Run・探索の完了を待ってから更新します（[更新手順の適用範囲](OPERATIONS.md)）。

1. 「プロファイルの保存・読み込み / Experiment」を開きます。
2. 「同梱のExperiment YAML」のチェックボックスで1件選び、「1件をエディタへ読み込む」を押します。ファイル名・実験名を表示します。モデル定義だけのYAMLは候補に入りません。
3. 最初は `tvt/00-smoke-sema.yaml` を使用してください。4 ED × 16生成、990秒の機能確認です。論文の性能値としては使用しません。
4. 「Abstruct · 設定一覧」と「設定を検証」で値を確認し、「エディタの設定を実行」からキューへ登録します。workerの起動方法は[運用](OPERATIONS.md)を参照してください。
5. 本実験では各YAMLのseedを `0, 1, 2, 3, 4` に変えて独立に5回実行します。同じ設定の反復は同じExperimentへまとめます。新しいYAMLを読み込むとExperiment選択をクリアします。

複数の設定をまとめて実行する場合は、例えば `tvt/` で絞り込み、「表示中を全選択」または個別チェックで選んで「選択したYAMLを一括実行」を押します。各YAMLの保存値で1 Runずつ順番に登録します。この操作だけではseed反復を増やしません。登録中は画面を開いておいてください。登録結果と失敗理由は項目ごとに表示します。[GUIの一括実行仕様](GUI.md)を参照してください。

1件の読み込みは設定エディタへの取り込みです。保存・実行は別操作です。既存の `model_files` 付き例も参照先を展開し、ブラウザから保存できる自己完結した入力に変換します。API認証は従来どおり適用されます。ソース・Docker・wheelに同じ例を同梱します。

| ED数 | 基本比較50 / 100 / 150 / 200、追加対照100 / 150 |
| 共通行動空間 | SF7〜12 × 868.1 / 868.3 / 868.5 MHzの18行動 |
| UL無線設定 | TP14 dBm、BW125 kHz、CR1（4/5）、プリアンブル8 symbols |
| 伝搬・干渉 | 現行LogDistance、指数3.76、基準距離1 m、基準損失7.7 dB、Goursaud行列 |

`max_messages`は生成数の上限です。実送信数は既存MACと終了時刻に従います。本条件では周期を60秒にし、最後のACK処理にも30秒の余裕を置きます。中断Run・編集した条件では最大送信通番、対象ED数、打切り数も確認してください。

PHY/MAC、干渉判定、伝搬式、感度表、RX窓、ACK形式、イベント順序、乱数ストリームの割り当ては変更していません。[設定仕様](CONFIGURATION.md)・[適用範囲](FIDELITY.md)に従います。

## 2. 移動環境

新規 `asset_waypoint` は既存Waypointの経路生成を再利用する独立プラグインです。共通400地点を一様配置し、各EDが初期地点を独立選択して**静止から開始**します。静止終了後は現在以外の地点を選び、訪問ごとに速度と静止時間を引き直します。地点集合のみRun内で共有し、EDの状態・乱数は共有しません。

| シナリオ | 静止時間 | 速度・地点 |
|---|---|---|
| `reference` | U[3,000,18,000]秒（50〜300分） | U[1,5] m/s、400地点、高さ1.5 m |
| `long_pause` | U[18,000,36,000]秒（300〜600分） | 同上 |
| `short_pause` | U[0,600]秒（0〜10分） | 同上 |
| `mixed` | 半数がlong_pause、半数がshort_pause | 同じ400地点を共有 |

真の移動状態と状態開始時刻は解析用に保存します。学習器は選択時の局所2D位置差 `> 1 m` で判定し、真の状態を学習入力に渡しません。

## 3. 比較手法と実験マトリクス

| YAMLの手法名 | 実装 / 比較の役割 |
|---|---|
| `sema` | 既存SEMA。共有A、静止B、移動C、静止ε-greedyと6メタ腕 |
| `dqn` | 既存1入力DQN。SEMA下位学習器と同じ報酬・更新則 |
| `epsilon` | 新規 `sf_reward_bandit`, `algorithm: epsilon`。累積報酬最大、ε=max(0.1,20/(20+t)) |
| `ucb1` | 同プラグインの `algorithm: ucb1`。元の報酬平均 + 2√(ln(t)/n)。未試行腕を先に1回ずつ選択 |
| `thesis_lora_mab` | 新規の修論式5.8〜5.11版。下記更新式 |
| `random_sf_ch` | 既存の共通18行動からの一様選択 |
| `lora_mab_sf_ch` | 補足比較：既存ACK 0/1報酬のLoRa-MAB SF×CH拡張 |
| `linucb_sf_ch` | 補足比較：既存LinUCB SF×CH拡張。受信した9 byteの追加DL通知を使用 |
| `dqn_mobility` | 新規対照。保持ACK RSSI＋局所移動ビットの単一2入力DQN |
| `dqn_state_split` | 新規対照。静止時B・移動時Cの固定2モデル。選択したモデルだけを更新 |

主比較6手法と補足2手法をreferenceの4 ED数で比較します。補足手法は報酬・利用情報の条件が異なるため手法名を分けて表示します。

修論LoRa-MABではK=18、T=40,000、γ=min(1,√(K ln(TK)/T))、α=1/T、`p_i=(1−γ)w_i/Σw+γ/K`。選択腕iだけを `w_i ← w_i exp(γr/(Kp_i)) + (eα/K)Σ_j w_j` と更新し、総和は更新前の値を使います。報酬は成功 `(13−SF)/6`、失敗−1。対数重みで同じ確率を安定に計算します。既存の原論文対応プラグインは置換しません。

| 実験群 | 条件 | YAML数 |
|---|---|---:|
| 基本比較 | 8手法 × 4 ED数 × reference × 幅64 | 32 |
| 移動環境・構造対照 | SEMA / DQN / DQN＋移動 / 固定B/C × 2 ED数 × 4環境、基本比較との重複4を除く | 28 |
| サイズ対照 | 同じ4手法 × 2 ED数 × reference × 幅16 / 32 | 16 |
| 合計 | 各5 seedsなら380 Run | **76** |

`scripts/generate_tvt_examples.py`でYAMLを再生成できます。実験ランナーではなく設定生成専用です。新しいモデルはGUIの通常の選択欄にも自動登録されます。

## 4. 学習器の共通設定

| 項目 | 全DQN系で固定する値 |
|---|---|
| 隠れ層・出力 | 64→64（サイズ実験は16→16 / 32→32）、ReLU、18出力 |
| 入力 | ACK RSSI 1要素。DQN＋移動のみ2要素。初期−120 dBm、不達時保持、offset0/scale1 |
| 経験再生 | 容量10,000、batch128、重複なし一様抽出 |
| 学習 | MSE、Adam、lr0.01、γ0.5、毎経験1更新（batchが揃ってから） |
| Target | 16勾配更新ごとに完全コピー |
| 探索 | 1→0.01、指数減衰の時定数1,000経験 |
| 下位報酬 | ACK成功 `(13−SF)/6`、失敗−1 |
| SEMA | メタ報酬ACK 0/1、信頼係数1、静止[A,B,ε] × 移動[A,C]。その状態のAとB/Cへ経験を共有 |

固定B/Cは2モデル、SEMAは3モデルです。サイズ実験でもそれぞれの実際の計算時間を測ります。チューニングは本番seedと分けた予備実験で設定を確定し、比較条件を保存します。

## 5. 必要な評価とGUIモジュール

「比較・分析」のモジュール追加欄で選択します。既存APIは一度に最大20モジュール・200 Runです。ED数・移動環境・サイズを揃えた比較群に分けて実行します。

| 評価 | モジュール | 送信範囲 / 図表 |
|---|---|---|
| E1 通信性能 | `tvt_quality`, 既存 `prr_by_count` | 38,001〜40,000。ED平均PRR、別計数のACK成功率、ED数依存性 |
| E2 公平性・下位品質 | `tvt_quality`, `tvt_seed_comparison` | 同上。Jain、ED別CDF、下位10%平均、PRR≥0.7のED割合、seed平均と95%区間、SEMAとの差 |
| E3 性能差の内訳 | 既存 `outcomes`, `spatial_sf`, `stationary_distance`, `channel_distribution`, `mobility_outcomes` | 同上。損失原因、位置別SF、距離別・状態別PRR、ED別/全体CH偏りとKL |
| E4 学習・戦略推移 | `tvt_learning`, 既存 `sema_pool`, `tvt_settlement`, `tvt_selection` | 1〜40,000。1,000回ごとの区間PRR、腕の残存、実選択、観測末の腕集合への到達 |
| E5 計算時間 | `tvt_cpu` | 全期間と終盤を別々に集計。推論・メタ更新・学習の平均/95%点/最大、PRRとの関係 |
| E6 構造と移動環境 | `tvt_quality`, `tvt_seed_comparison`, `tvt_selection` | 4手法×4環境。真の状態と局所判定の混同行列、距離・状態別の実選択と条件付きPRR |
| E7 移動開始・停止への応答 | `tvt_transitions` | 2,001〜40,000、burnin=2,000、H=10/50/100。遷移後PRR、完全窓の損失、不完全窓数 |
| E8 モデルサイズ | `tvt_quality`, `tvt_cpu`, `tvt_seed_comparison` | 幅16/32/64、ED100/150。品質と計算量。対応差ではSEMAの基準サイズを一つ選択 |

表はCSV、全データはJSONで保存できます。既存 `prr_by_count` の縦線はRunの最小〜最大です。95%信頼区間は `tvt_seed_comparison` の表を使用します。

### 集計の定義

- PRRは判定済みULのED別成功割合をED等重みで平均します。打切りULは分母から除き、対象ED数と全ED数を併記します。ACKはフィードバック確定済み試行のパケット加重成功率です。
- 下位10%平均は `ceil(対象ED数×0.1)` 台の平均で、10%分位点とは別です。Jainは全PRR=0では未定義と表示します。
- seed集計は環境・実効モデル・実装hash・依存版を照合し、独立seedの平均に95% percentile bootstrap（5,000反復、解析seed2026）を適用。同一seedの重複を独立反復に数えず、1 seedでは区間を作りません。対応差は同条件・同seedの「SEMA−比較手法」。基準設定が複数なら差を集計せず理由を表示します。
- `tvt_learning` は非重複区間のED平均PRRです。任意の終盤正規化はRun末の各EDの最後の2,000送信を基準にします。
- `tvt_settlement` は観測末の生存集合と初めて一致した通番を事後的に示します。生存腕数、実際の下位モデル選択、性能の学習推移を別々に確認できます。
- `tvt_selection` の割合は実送信の選択回数、条件付きPRRはその選択時の判定済みULに対する割合です。選択前の状態・距離・経験が違うため、E6の独立対照Runと併用します。局所判定は選択時、真の状態は送信時で、MAC待機がある場合は時刻差も含みます。
- 遷移評価は真の状態開始時刻で整列し、初期状態を除きます。同一状態区間の最初のH送信が全て判定済みなら完全窓とし、損失率を窓等重みで平均。次の状態へ続けて数えません。短い区間・終端・送信番号欠落は不完全窓。PRR曲線は各点の標本数を併記。送信を含まない状態区間は対象外です。

Parquetをバッチ読み込みし、正確なCPU分位点と遷移順序の並べ替えには一時SQLiteを使用します。パケット全件をPythonのリストやDataFrameに保持しません。

## 6. 実行時間

`tracking.policy_diagnostics` を有効にすると `process_time_ns()` で各EDの選択とフィードバック処理を測ります。

| 表示名 | 測定範囲 |
|---|---|
| `inference` | メタ選択を含む行動選択全体 |
| `training` | メタ更新を含むフィードバック処理全体 |
| `meta_update` | SEMAのメタ報酬・回数更新と消去。他手法は0 |
| `decision_plus_meta` | 同じED・送信通番のinference＋meta_update。DQN学習は含まない |

CPU時間はホスト実測です。simulation timeや既存MCUエネルギー設定へフィードバックしません。未送信の選択は通番0で記録して通常集計から除外。Run全体の実時間は従来の `summary.wall_s` に保存します。実行環境の固定は強制せず、manifestの環境情報と並列実行条件を測定記録に残してください。

## 7. 修論・現行実装・今回の対応

| 項目 | 今回の扱い |
|---|---|
| 初期静止 | `asset_waypoint`を追加。既存Waypointの初期出発は変更しない |
| 40,000回 | `finite_periodic`を追加。既存周期モデル・MACは変更しない |
| UCB1 | 修論の未正規化SF報酬と係数2を別プラグインで指定 |
| LoRa-MAB | 修論式版と既存ACK報酬版を別名で保持 |
| RSSI・移動判定・探索減衰等 | [SEMA.md](SEMA.md)で明示した未指定事項の補完を維持し、YAMLとOptionsで固定 |
| ACK・DL電力・RX窓 | 現行を維持。標準ACK9 byte、RX2は既存サブバンドの27 dBm、8 symbol待受。修論の12 byte ACK / 14 dBm一律DL / 固定長窓へ変更しない |
| 感度・干渉・伝搬 | 現行を維持。GW感度SF7〜12は−130, −132.5, −135, −137.5, −140, −142.5 dBm |
| 不足する記録 | CPU時間、送信通番付きACK、状態開始時刻、実選択モデル、局所移動判定を追記 |

動作確認は機能検証と短いシミュレーションです。76設定×5 seedsの本実験は実行していません。旧修論の数値を今回のRun結果として流用せず、この条件で出力された結果から図表を作成します。
