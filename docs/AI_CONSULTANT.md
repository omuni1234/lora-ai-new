# AIコンサルタント（v0.14）

「比較・分析」と「Calculator」から、実験の設定・集計結果についてAIと継続会話できます。回答は受信したテキストから順次表示します。AIに実験の実行・設定変更を行う権限はありません。

## 最初の接続設定

右上の「接続設定」→「OpenAI API接続設定」、または相談画面の「OpenAI接続設定」を開きます。

| 設定 | 内容 |
| --- | --- |
| 接続先エンドポイント | OpenAIは `https://api.openai.com/v1`。`/responses`・`/chat/completions`までのURLもベースURLへ正規化します。 |
| API形式 | Responses API / Chat Completions API。新規GUI入力ではResponsesを提示。接続先とモデルが対応する形式を選択します。 |
| モデル名 | 自分のAPIプロジェクトで利用可能な正確なモデルID。モデルを自動で置き換えることはありません。 |
| API Key | パスワード入力。保存後は「設定済み」のみ表示します。空欄で保存すると既存キーを維持します。 |
| 出力トークン上限 | 1〜128,000。モデル自体の上限はAPIに依存します。GUI新規入力の目安は8,000。推論モデルでは推論用トークンも含みます。 |
| 待機時間 | 10〜600秒。1回の相談全体の上限です。 |

保存はサーバーのデータ領域の `private/ai-settings.json` に原子的に行います。ファイル権限は0600、作成するディレクトリは0700。暗号化Vaultではなくローカルファイル保存です。キーはブラウザーのlocalStorage/sessionStorage、プロファイル、分析JSON、通常ログには保存しません。バックアップでデータ領域をコピーする場合、このファイルにはキーが含まれることに注意してください。

保存だけで外部APIには接続しません。以後の相談から即時に適用され、API/workerの再起動は不要です。Docker Composeの`results` volumeに永続化されます。設定は同じデータ領域の利用者で共有します。既存の `LORASIM_API_TOKEN` を設定していれば、設定変更・データ確認・相談にもその認証を適用します。

優先順位は **GUI保存値 > APIプロセスの環境変数** です。GUI保存後に.envだけ変更しても上書きしません。「環境変数の設定に戻す」でGUI設定ファイルを削除し、環境変数へ戻せます。「保存済みキーを削除」はキー無しのGUI設定を保存するため、環境変数のキーも使いません。

接続先URLを変更する場合、以前のキーを別サービスへ自動転送しないよう、新しいキーの入力またはキー削除を必要とします。リダイレクトには追従しません。

## 比較・分析から相談

1. 左でExperimentと送信回数範囲・ED数・MCUの扱いを選び、分析モジュールを設定します。
2. 「選択した実験を分析」を実行します。
3. 中央上部の「AIコンサルタント」へ切り替えます。
4. 「分析結果を相談データにする」を押します。「AIに送る集計データを確認」で内容を確認できます。
5. 質問を入力して「AIに相談する」を押します。接続先が未設定でも、相談画面内から設定して続けられます。
6. 回答は逐次表示されます。同じデータに対して続けて質問できます。「回答を停止」「新しい会話」「会話を保存」も利用できます。

相談データに含むもの：

- **選択して集計されたRunだけ**のPRR、損失内訳、公平性、観測数、判定未了、消費エネルギーなど。未計測エネルギーは数値0として送らず、未計測であることを示します。
- 分析リクエストのExperiment、送信回数、ED数、MCU、モジュールとそのオプション。
- 有効にして集計したモジュールの結果・定義・注意書き・失敗時診断。
- 各Runの保存プロファイル。実際に参照したモデル定義を展開し、現在のライブラリで置き換えません。未使用ライブラリ定義は除外します。
- 開始・終了時刻、保存された実行環境とシミュレータ版（記録がある場合）、条件ハッシュ。

`condition_sha256` は名前・seed・tracking・notificationsを除いた展開後プロファイルのハッシュです。違いを見つける補助であり、同じハッシュだけで全実行環境やPythonプラグインの同一性を保証しません。seedはプロファイルに明記されます。

AIはUL受信とACK成功を区別し、観測のないED、累積1〜tと区間集計、未計測エネルギー、seed不足、実験条件の交絡を考慮するよう指示しています。**考察は仮説を含みます。数値の根拠は分析表と保存プロファイルに戻って確認してください。**

### 速度・送信量・古い結果の扱い

相談のたびにシミュレーションやParquet走査を行いません。分析完了時に集計結果と保存条件から相談用のスナップショットを作成します。元の集計結果・グラフを変更しません。

送信コンテキストはUTF-8で180,000 byte以下。Run別の主要集計値は全件維持し、長い配列・時系列・地図セル・モデルの座標などは端点を含む等間隔の添字で標本化します。表は列と行内の値の対応を維持します。配列上限を100→40→16→6→2へ下げても入らない場合は対象を絞るよう表示します。長い文字列は6,000字で省略します。`sampling.omissions`に箇所・元件数・残した添字等を記録します。標本化されたデータだけから細かな位置差や局所的な収束は判定できません。

スナップショットは`consultant/analyses/`に直近20件を保存します。これ以上の分析で古いものが削除された場合は再分析します。集計条件・モジュールを変更すると送信を無効にし、再分析とデータ準備を要求します。続けて質問している途中で別の実験結果が混入しません。

## Calculatorから相談

「実験前の設定確認」→「Calculator」→「AIコンサルタント」で、編集中のプロファイルまたは保存済みRunを選択し、「送信データを確認する」を押します。近似予測は任意に添付します。プロファイル編集や相談対象変更時には準備済みデータを無効化します。

比較・分析と同じ接続設定・会話・ストリーミング処理を利用します。**近似予測と実測は異なる根拠**です。AIへも別の項目として渡します。

## 会話とストリーミング

実装は[公式OpenAIのストリーミング仕様](https://developers.openai.com/api/docs/guides/streaming-responses)に従います。Responsesでは`response.output_text.delta`、Chat Completionsでは`choices[].delta.content`を受信し、サーバーからGUIへSSEで中継します。回答が返ってから文字送りを演出する方式ではありません。

- Responsesでは`max_output_tokens`、Chat Completionsでは`max_completion_tokens`を使います。両方とも`stream:true`・`store:false`を指定し、履歴は毎回明示的に渡します。独自互換サーバーにはこれらの引数とSSEへの対応が必要です。
- 推論中に本文がない間は「考察中」。最大10秒間隔でkeepaliveを送ります。非公開の推論内容は表示しません。
- 会話履歴はこのページのメモリー内だけに保持。自動永続化しません。再読み込み前に「会話を保存」でJSONをダウンロードしてください。履歴は最大12往復・120,000 byteまで。次の相談で上限を超える場合は新しい会話を案内します。
- 生成停止や接続断では途中までの回答を残し、未完了と明示します。途中切断した回答は次回の履歴に含めません。正常に受信できた上限到達の回答には「途中」と表示します。
- 受信途中のキャンセル・ブラウザー切断で上流HTTP接続を閉じます。プロバイダー側で既に発生した処理・課金を取り消す保証ではありません。通常のバックグラウンド実験は影響を受けません。
- 回答テキストはHTMLとして実行せず、プレーンテキストで描画します。
- 同一APIプロセスのストリーミング相談は最大4件。自動再送は行いません。複数プロセス運用なら各プロセス単位の上限です。

リバースプロキシを使う場合はSSEのバッファリングを無効にし、read timeoutを相談の待機時間以上にします。APIは`X-Accel-Buffering:no`・`Cache-Control:no-store`を返します。

## 環境変数からの設定

既存の.env設定も利用できます。ネイティブ起動は自動で.envを読み込まないため、起動プロセスへ渡してください。Composeでは以下をAPIサービスへ渡します。

```dotenv
LORASIM_AI_BASE_URL=https://api.openai.com/v1
LORASIM_AI_API_TYPE=responses
LORASIM_AI_MODEL=<利用可能なモデルID>
LORASIM_AI_API_KEY=<自分のキー>
LORASIM_AI_MAX_TOKENS=8000
LORASIM_AI_TIMEOUT_S=180
```

`API_TYPE`未指定の既存環境は互換性のため`chat_completions`を使います。既存の出力上限の既定は2,000を維持します。推論モデルで可視回答前に枠を使い切る場合はGUI等で増やしてください。

環境変数変更をComposeへ反映する場合は `docker compose up -d --no-deps --force-recreate api`。単なる`restart`では変数を更新しません。v0.14へのコード更新時はhttpx依存も増えるためイメージを再ビルドしてください。

## エラーへの対処

| 表示 | 確認すること |
| --- | --- |
| 未設定／送信ボタンが無効 | モデル・キーを設定し、相談データを準備。分析条件を変えた後は再分析。 |
| HTTP 400 | API形式、モデル、入力長、出力上限、互換サーバーの引数対応。 |
| HTTP 401 / 403 | キーの有効性、プロジェクトとモデルの利用権限。 |
| HTTP 404 | URL、API形式、モデル名。 |
| HTTP 429 | 利用枠、残高、送信頻度。 |
| 表示できる回答なし／出力上限 | 推論だけで上限に達する場合、出力上限を増やすか質問・添付データを絞る。 |
| ストリーム形式ではない | HTMLページ・非SSE互換サーバー等を指定していないか確認。 |
| 回答が途切れた／待機時間超過 | ネットワーク・プロキシ・待機時間。途中の文章を完成した結論として扱わない。 |

## 開発者向けAPI

- `GET /api/consultant/config`: 秘密を除いた有効設定。キーは`key_configured`だけ。
- `PUT /api/consultant/config`: `base_url,api_type,model,api_key?,clear_key,max_tokens,timeout_s`を保存。
- `DELETE /api/consultant/config`: GUI保存値を削除し、環境変数へ戻す。
- `POST /api/analysis`: 通常結果に`consultant_snapshot`を追加。相談データが大きすぎる・保存不可でも分析グラフは維持し、`error`を返す。
- `GET /api/consultant/analysis/{id}`: 固定された相談データと接続設定。
- `POST /api/consultant/preview`: Calculator用相談データの準備。外部送信なし。
- `POST /api/consultant/stream`: `{analysis_id?,context?,question,history:[{role,content}]}`。分析IDを指定するとサーバーの固定結果を使い、送られたcontextは無視。SSEの`type`は`start,heartbeat,delta,done,error`。
- `POST /api/consultant/ask`: 旧一括応答APIを維持。新GUIはstreamを利用。

責務は`ai_settings.py`（接続設定）、`consultant_analysis.py`（分析根拠）、`consultant.py`（会話・API中継）、`static/consultant.js`（GUI）に分離しています。シミュレーションイベントループとPHY/MACの数式には関与しません。
