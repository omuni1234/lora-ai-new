# v0.13 ハイパーパラメータ調整の検証

新規の探索制御、API、GUIを対象に検証しています。PHY/MAC・伝搬式・選択アルゴリズムの学習則は変更していません。

- 段階的絞り込み・網羅探索・局所探索の進行、独立した確認seed、元定義との比較。
- 悪化候補の確率的受理、同予算の再利用、失敗seedだけを除いて平均しないこと。
- 参照定義の固定、同一段階の重複投入防止、中止時の他Runとの分離。
- 新しい名前への保存、上書き拒否、行動空間維持、未評価候補の保存拒否。
- 独自Options、入れ子の送信タイミング、移動の相互制約、共通行動空間で無効な項目の拒否。
- 実際のspawn workerを2並列で起動し、ブラウザーなしで探索から確認・保存まで完了。
- ローカルのControl Centerから、epsilon候補登録→予算確認→探索開始→結果表示→新規ライブラリ保存を操作。

実行環境はローカルのmacOS / Python 3.11です。Python **357件成功**（16.01秒、既存のStarlette/httpx非推奨警告1件）、JavaScript **19件成功**。結果ログは `validation/tests-tuning-v013.txt` と `validation/tests-tuning-ui-v013.txt` に保存しています。

GUIでは10 ED、epsilonの3候補、180/600秒、探索seed 1・2、確認seed 101・102で、7候補段階・計14 Runを完了し、`bandit-epsilon-tuned-ui` を保存しました。再読み込み後に探索結果と保存済みモデルが表示されることも確認しています。UIで利用した小規模条件は操作検証用で、アルゴリズムの優劣を示す研究結果ではありません。Ubuntu/Docker実環境での再デプロイはこの検証には含みません。

同梱 `examples/tuning_bandit.py` もv0.13.0のworkerで実行し、24 Run・12候補段階を正常完了しました。詳細は `validation/tuning-example-v013.json`。wheelのビルドと、探索モジュール・画面・マニュアルの同梱も確認しました。
