# 実験前のトレードオフ予測（v0.10.0）

## 使い方

「実験前の設定確認 → Calculator → トレードオフ予測」で **プロファイルから予測する** を押します。編集中のGUIプロファイルとモデルライブラリを読み、Runを登録せずに計算します。YAMLの未適用編集は「GUIに反映・検証」してから使います。

主グラフは **各EDのUL試行における割合をED間で等重み平均** したものです。成功は少なくとも1つのGWで受信したこと。ACK成功率・生成メッセージの到達率・学習後の性能とは区別します。JSONには送信数で重み付けした `packet_fractions` も保存します。

比較行は次を一つずつ変え、その他の条件を維持した診断です。

- 全EDのSFを全体候補の各SFへ固定する。
- 送信間隔を0.5倍／2倍にする。
- ACKをなくす。学習器のACK必須条件を満たさない場合があるので診断専用。
- 全体候補の先頭1 CHへの集中／全候補CHの均等利用。
- 同じ配置分布でED数を2倍にする。
- TPが複数候補なら最小値／最大値へ固定する。

ED個別の候補制限を上書きする比較も含みます。プロファイルへ自動適用しません。EUペイロードやサブバンドの上限に違反する比較は、割合を作らず理由を表示します。

### 読み方で重要なこと

このシミュレーターは、GW送信中ならそのULを先に拒否します。受信中にDL送信を開始した場合もULを中断します。そのため、GW送信が減るだけで、従来隠れていた干渉や感度未満へ分類される割合が増えることがあります。**原因の構成割合が増えたことだけでは、電波条件そのものが悪化したとは言えません。**

これを区別するため、以下を併記します。

- **潜在干渉**：少なくとも1つの受信候補GWがあるEDに条件付け、GW送信と復調器制限を除いて計算した干渉失敗率。候補がない場合はN/A。
- **受信候補GWなし**：どのGWでも、CH・受信感度の条件を満たさない割合。
- **GW送信占有率**：時間のうちGW自身が送信している割合。UL途中の中断を含む `LostBecauseTx` とは異なるため、両者は一致しません。

3損失のうち、ある原因が0.5ポイント以上減り、別の原因が0.5ポイント以上増える比較を「トレードオフの兆候」として列挙します。0.5は表示上の目安であり、有意差検定や研究上の閾値ではありません。

## 採用した方法と理由

**配置・行動の有限標本＋Poisson重複エネルギー＋ACK送信可用性の固定点近似**です。

単純なPure ALOHAの `1 − exp(−2λT)` だけでは、SF間干渉、受信電力差によるcapture、ACKがGWの受信を止める作用を分離できません。一方、全期間のイベントシミュレーションは実験条件の探索に重すぎます。その間を取って、代表的なULの周りだけを確率的に積分し、UL成功とACK負荷の循環を平均値で解きます。

UL/DL負荷を連立させ、サブバンドの可用性をrenewal過程で表す着想は [Magrin et al., A Configurable Mathematical Model for Single-Gateway LoRaWAN Performance Analysis](https://arxiv.org/html/1912.01285v2) を参照しました。同論文の完全な再現実装ではありません。同論文で単純化されているcaptureとSF間干渉については、当シミュレーターのエネルギー式・Goursaud行列を使用します。採用した近似と境界を以下に明示します。

### 1. 配置と行動分布

既存の配置プレビューから最大128 EDを抽出し、各グループの台数を標本の重みに戻します。初期配置の乱数系列と対応します。移動は `snapshot_s` の位置のみで、全軌跡を積分しません。移動の処理上限に達する場合や独自移動では初期位置に戻り、Warningを出します。標本に入らないグループがある場合はエラーにします。

- fixed：実装と同じ固定Radio。共通行動空間、プリアンブル・CRC等も反映。
- ADR/BADR/GADR：初期SF/TPを保持し、設定されたCH分布を使用。制御の進行やMAC commandは予測しない。
- random：その候補を均等に利用。
- 学習器：候補を均等に利用する仮定。学習や推論を呼ばない。
- 独自選択器：全体／ED候補の均等利用で代替することをWarningで明示。

大きい候補集合は各EDにつき最大8候補を一様抽出します。直積は遅延評価し、大きい配列へ全Radioを展開しません。選択比率と位置の相関、学習後の方策、ED間の競合適応は未知として扱います。

### 2. UL干渉の確率積分

代表UL i の長さを `Ti`、他の送信クラス j の発生率を `λj`、長さを `Tj` とします。同じ周波数の信号が重なる始点区間は `(-Tj, Ti)`。各区間への到着数は

```
Kij ~ Poisson(λj (Ti + Tj))
開始位置 ~ Uniform(-Tj, Ti)
overlap = max(0, min(Ti, start + Tj) − max(0, start))
```

とし、SF別に `overlap × 受信電力` を加算します。希望信号の全送信エネルギーとの比を本体と同じ行列で判定します。単独では弱い複数信号の合成、SF間干渉、captureを扱います。感度未満や復調拒否されたULも干渉へ含めます。ALOHA設定では同じSFの重複だけを失敗にします。自分自身のULを混ぜません。

各候補32〜512回（既定96回）で積分するだけなので、20,000回等の本実験の送信回数をループしません。EDの位置標本化のための初期配置乱数消費はED数に比例します。

### 3. GW・ACKの連立

感度・CH条件を満たすULが占有する復調器の負荷を `A` とし、Erlang Bで新しいULのブロック率を近似します。

```
B(0, A) = 1
B(k, A) = A B(k−1, A) / (k + A B(k−1, A))
```

GWのDL送信占有率を `ρ`、DL開始率を `ν` とします。ULの開始時にGWが空いている確率を `1−ρ`、受信中に送信開始しない確率を `exp(−ν Ti/(1−ρ))` とします。後者がないと長いULの `LostBecauseTx` を過小評価します。Class Aの同じED自身のUL/ACKは重ならないので、そのED由来のDLを露出から除きます。

損失は本体の順序に合わせて分解します。

1. 開始時のGW送信中
2. 周波数不一致
3. 感度未満
4. 復調器不足
5. 受信中のGW送信開始（1とまとめてGW送信中へ）
6. 干渉／受信成功

成功したconfirmed ULからACK需要を生成します。GWは成功確率とRSSI順位に基づき配分し、RX1が使えなければRX2へ回します。各サブバンドのACK送信時間を `Td`、Duty Cycleを `δ` とすると可用性は、他バンドのGW送信占有も差し引いたrenewal近似

```
a_b ≈ (1 − ρ_other_bands) / (1 + Σ offered_ACK_rate × Td/δ)
```

で計算します。Duty Cycle無効時はδ=1。RX1/RX2のSFと周波数・許可DLサブバンド・TPはプロファイルから取得します。ACKサイズは本体と同じ9 byte、LinUCBのリンク通知には9 byteを追加。ADR commandの追加分は含みません。

UL成功、ACK量、GW可用性を0.5で緩和して反復し、最大残差が `1e-5` 未満になれば収束とします。上限40回で収束しなければWarningと残差を返します。この実装について任意条件での収束を証明していません。

再送の反復中、UL発生率が前回から2.5%以上変わったときだけ干渉の標本計算をやり直します。これは計算量を抑える追加近似です。

再送は、ACKの送信可用性とED感度から求めた `pACK` に対し、期待試行数 `Σ(1−pACK)^k` で近似します。未確認は指定の繰り返し数です。EDの単一未完了メッセージ、平均Class A処理時間、2秒の平均再送待ち、Duty Cycleで試行率を制限します。多サブバンドのED待ち、DL衝突や他宛てDLへの先着ロック、時刻相関は省略します。

### 4. 複数GW

最大8 GW。条件付き受信を独立とした `1−Π(1−pg)` を主値にします。他GWのDL干渉・GW間相関・ACK候補GWの再選択を省略します。相関が未知な場合の成功率の範囲 `max(pg)〜min(1,Σpg)` を併記します。この範囲もモデル誤差を含む信頼区間ではありません。全GWで異なる理由で失敗する確率はMixedLossへ分類します。

## 信頼してよい範囲と限界

非同期化された周期送信、またはPoisson送信の **定常的な傾向探索** を主対象とします。同期開始・同じ位相を維持する周期、短時間実験、強い再送負荷、移動と選択の相関、少数EDへの特殊な割当では精度が落ちます。開始時刻が実験終了以降なら計算を拒否します。独自送信タイミングは平均間隔の明示入力が必要です。

乱数seed・標本数・重複試行数を変えても残る傾向を使い、候補を絞った後に本シミュレーターで確認してください。推定の小数点以下を過信しないでください。4条件で本体と比較した結果と最大6.23ポイントの損失内訳差を [検証記録](VALIDATION-v010.md) に示します。

## API・拡張・計算上限

`POST /api/calculator/forecast` に `yaml` と `options` を渡します。実装は `lorasim/tradeoff.py`、GUIは `lorasim/static/planning.js`。元のPHY/MACは変更しません。

```json
{"options":{"seed":73,"device_samples":48,"overlap_trials":96,"snapshot_s":0,"action_mode":"profile","custom_interval_s":null,"compare":true}}
```

タイミングの追加は `interval`、選択分布は `candidates`、損失とACK連立は `scenario` に分離しています。プラグインの `select/observe` は呼びません。参照とassignmentsは標本EDに適用してから候補を決めます。

出力は `model`、プロファイルのSHA-256、仮定、標本数、比較条件、ED等重み・送信数重みの割合、潜在指標、GW占有率、収束状態、Warning、実時間を含みます。「予測JSONを保存」で後段の分析へ渡せます。

上限は128標本ED、8候補/ED、8 GW、64グループ、CH比較4096粒子、全条件で500万の重複信号、1候補あたり期待20万の重複信号です。上限では明示的に失敗し、黙って干渉を切り捨てません。Run・パケット履歴は保存せず、リクエスト時にだけ動作します。
